# LMS-085 — Course Management UI

## Scope

Implements the Course overview actions, protected Course create route, tenant-scoped Course management detail route, metadata edit form, DRAFT delete confirmation, and existing Preview links. This ticket does not implement Module/Lesson authoring, learner access, a new Course API, lifecycle changes, or a Prisma schema/migration.

## Routes and API contracts

- `/admin/courses` offers **New course**, **Manage**, and **Preview**, with the required create-oriented empty state.
- `/admin/courses/new` checks the existing server Admin access flow and submits title/description to `POST /api/organizations/courses`.
- `/admin/courses/:courseId` authorizes on the server, obtains the trusted `requireTenantContext()` organization, then reads with `courseStore.get(organizationId, courseId)`. Malformed, missing, and foreign IDs use the same `notFound()` behavior.
- Metadata edits use `PATCH /api/organizations/courses/:courseId`; DRAFT delete uses `DELETE` on that endpoint with JSON `{}`. The browser submits no tenant, status, or server metadata fields.
- Preview continues to use `/courses/:courseId/preview`.

## Behavior and security

OWNER and ADMIN with `MANAGE_COURSES` are allowed by the existing server authorization. MEMBER is denied. The backend remains authoritative for validation, lifecycle, and tenant scoping. UI validation mirrors backend Unicode code-point limits. PUBLISHED metadata can be edited and previewed; published deletion is unavailable in the UI and backend `409 published_course_delete_forbidden` is mapped to a safe race message. Requests disable duplicate submissions, preserve create input after failure, and never render raw API error bodies. Successful metadata edits refresh server data; deletion returns to the Course list and refreshes it.
