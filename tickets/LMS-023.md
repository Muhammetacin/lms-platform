# LMS-023 — Course Publishing

## Objective

Implement the first safe Course lifecycle transition, `DRAFT → PUBLISHED`, with organization-scoped authorization, publication completeness checks, a stable timestamp, PostgreSQL lifecycle enforcement, idempotent retries, and serialization with Course Module/Lesson mutations.

## Product decisions

- Publishing is the only lifecycle transition in this ticket. There is no unpublish endpoint, generic status patch, Course versioning, learner preview, assignment/enrollment/progress/certificate flow, Quiz model, storage/upload work, audit subsystem, or notification.
- Course title and description edits remain available after publication under LMS-019. Course structure/content changes remain locked. Published Courses remain protected from generic deletion.
- `QUIZ` Lessons block publication until a later Quiz ticket provides a real model and completeness contract.
- LMS-024 owns preview and rendering. URL validation is syntax-only and performs no network, DNS, MIME, or availability request.
- LMS-058 owns audit logging; LMS-023 adds no parallel audit mechanism.

## Lifecycle

The only supported transition is `DRAFT → PUBLISHED`. Repeat publish returns the existing published Course with HTTP 200. There is no `PUBLISHED → DRAFT` transition and no unpublish endpoint.

## publishedAt

`Course.publishedAt` is nullable. DRAFT Courses use `NULL`; a successful first publication writes one server-generated timestamp in the same transaction as `status = PUBLISHED`. Retries preserve it. The normal Course list, create, detail, and update responses include the field; new drafts return `null`.

## API

`POST /api/organizations/courses/:courseId/publish` accepts exactly the JSON object `{}`. Unknown keys, a missing body, non-object JSON, and oversized bodies are rejected. Success is `200 { course }`; incompleteness is `409 { error: "course_not_publishable", issues, truncated }`. Malformed, foreign-tenant, and missing Course IDs all return `404 course_not_found`.

## Authorization

The endpoint uses the existing `MANAGE_COURSES` permission. OWNER and ADMIN are allowed; MEMBER is forbidden; anonymous callers are unauthenticated. No new role or capability is introduced. All responses set `Cache-Control: no-store`.

## Tenant isolation

The handler requires `requireTenantContext()` and passes only `tenant.organizationId` to the store. Course lock/lookup predicates include both Course ID and Organization ID. Client query parameters and organization/tenant headers do not change the trusted tenant. Foreign and missing Courses share the same safe response.

## Completeness rules

- A Course needs at least one Module (`course_requires_module`).
- Module positions must equal contiguous `1..N` (`module_order_invalid`).
- Every Module needs at least one Lesson (`module_requires_lesson`, with `moduleId`).
- Lesson positions within each Module must equal contiguous `1..N` (`lesson_order_invalid`, with module and Lesson identifiers).
- TEXT Lessons need valid, non-blank `parseLessonTextContent()` content.
- VIDEO, PDF, IMAGE, and LINK Lessons need valid, non-blank HTTPS `parseLessonUrl()` content. The validator is also applied to direct database values.
- Missing/invalid non-Quiz content returns `lesson_content_missing` with `moduleId`, `lessonId`, and `type`.
- QUIZ Lessons return `quiz_not_configured` with `moduleId` and `lessonId`.
- Publishing never repairs ordering or rewrites lesson content.

## Issue contract

Issues are deterministic: Course-level first, Module position/ID order next, then Lesson position/ID order. The response includes at most 100 issues; `truncated` is true when additional issues exist. Codes and identifiers are machine-readable. No prose-only completeness error is returned.

## Concurrency / locking

The Prisma store opens a single transaction and selects Course `status` and `publishedAt` from the row matching both trusted `organizationId` and `courseId`, using `SELECT ... FOR UPDATE`. It retains that lock through completeness reads and the status/timestamp update. LMS-020 Module mutations and LMS-022 Lesson mutations use the same scoped Course-row lock. Concurrent publish requests serialize and keep one timestamp. Course deletion races resolve as either delete-first/publish-not-found or publish-first/delete-conflict. Completeness failure leaves the Course DRAFT with a null timestamp.

## Database constraints

The migration adds nullable `Course.publishedAt`, backfills existing PUBLISHED rows from `updatedAt`, and then creates `Course_status_publishedAt_check`. The CHECK accepts only DRAFT/null and PUBLISHED/non-null. No destructive reset is used.

## Unit tests

`tests/course-publishing.test.ts` covers exact empty-body parsing, malformed ID and safe not-found mapping, OWNER/ADMIN/MEMBER/anonymous authorization, issue response/truncation, no-store headers, untrusted requests, and generic safe storage failures.

## PostgreSQL tests

`tests/course-publishing-postgres.test.ts` uses production handlers/stores against the configured PostgreSQL database. It covers empty/empty-module Courses, missing/blank/invalid TEXT, missing/invalid VIDEO URL, valid TEXT/VIDEO/PDF/IMAGE/LINK content, QUIZ blocking, module and lesson position gaps, deterministic multiple issues, >100 issue truncation, complete multi-module publication, lifecycle CHECK cases, repeat publish, publish/publish, publish/Module, publish/Lesson, and publish/delete races, cross-tenant and forged tenant inputs, and post-publish immutability/deletion behavior.

## Regression tests

Existing PUBLISHED fixtures now set `publishedAt` to satisfy the database invariant. LMS-019 Course CRUD tests continue to cover tenant isolation and deletion protection; LMS-020 and LMS-022 tests remain in CI and continue to cover published structure locks and shared Course-row mutation locking. The Course model test checks `publishedAt` on a PUBLISHED row.

## CI

Adds `test:course-publishing` and `test:course-publishing:db` scripts and preserves the existing CI database migration, auth/tenant/employee/team tests, Course/Module/Lesson suites, lint, typecheck, and build. Final completion requires a green GitHub Actions run for the exact latest PR head SHA.

## Scope boundaries

No unpublish, versioning, learner preview/page, assignment, enrollment, progress, certificate, Quiz model/questions, upload/storage, remote URL fetch, audit subsystem, or notification was added. External QA/security review remains required.
