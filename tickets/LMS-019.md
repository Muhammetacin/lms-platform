# LMS-019 — Course CRUD

Status: CODE COMPLETE — READY FOR QA/SECURITY REVIEW

## Objective

Deliver organization-scoped list, create, detail, update, and delete operations for the LMS-018 Course model. LMS-019 is administrative Course management; it does not provide learner visibility, modules, lessons, publishing, or audit infrastructure.

## Product decisions

- `OWNER` and `ADMIN` can use all Course CRUD endpoints through the existing `MANAGE_COURSES` capability. `MEMBER` is denied for list, detail, and mutations.
- Course titles are not unique. Duplicate titles may exist within and across organizations.
- A new Course is always `DRAFT`; callers cannot supply or change status.
- Metadata edits are allowed for both `DRAFT` and `PUBLISHED` Courses.
- Only `DRAFT` Courses may be hard-deleted by generic CRUD. Published deletion returns `409 published_course_delete_forbidden`.
- LMS-058 owns audit integration; no separate audit log is introduced.

## API

| Method | Path | Behavior |
| --- | --- | --- |
| GET | `/api/organizations/courses` | Up to 100 tenant Courses ordered by `createdAt DESC, id DESC` |
| POST | `/api/organizations/courses` | Create a DRAFT and return `201` |
| GET | `/api/organizations/courses/:courseId` | Return one tenant Course |
| PATCH | `/api/organizations/courses/:courseId` | Update title and/or description |
| DELETE | `/api/organizations/courses/:courseId` | Delete a DRAFT or return published-delete conflict |

Course responses contain only `id`, `title`, `description`, `status`, `createdAt`, and `updatedAt`. Every success and error response sets `Cache-Control: no-store`. Mutations use `isTrustedAuthRequest` for same-origin JSON checks.

## Validation

- Create accepts only `title` and optional `description`; status, tenant identifiers, identity/ownership fields, timestamps, and all unknown fields are rejected.
- PATCH accepts only `title` and `description`, and requires at least one field.
- Titles are trimmed strings from 2 through 160 Unicode code points.
- Descriptions accept string or null, trim surrounding whitespace, normalize blank text to null, and have a 4,000 Unicode code-point maximum.
- Both values reject control characters and unpaired surrogates. They remain plain text; no HTML/rich-text parsing is added.
- Course IDs are validated before database access. Malformed, missing, and foreign IDs have the same `404 course_not_found` result.

## Authorization

Every endpoint calls `requireTenantContext()` and then `requireOrganizationPermission(tenant.organizationId, "MANAGE_COURSES")`. No new roles or capabilities are introduced. `MEMBER` has no generic Course-read capability.

## Tenant isolation

The client cannot select the tenant. The trusted `tenant.organizationId` is passed to the store. List filters by organization; detail, update, and delete include both Course ID and organization ID in their database predicates. Tenant query parameters and organization headers are ignored. The response select excludes `organizationId` and all other internal security data.

## Delete semantics

The production store scopes the status read by Course ID and organization ID, then deletes only with a conditional `id + organizationId + status: DRAFT` predicate inside a transaction. A concurrent publish therefore prevents deletion. Results map to `deleted`, `not_found`, or `published`; the handler exposes the stable conflict code `published_course_delete_forbidden` for published rows.
