# LMS-018 — Course Model

Status: CODE COMPLETE — READY FOR QA/SECURITY REVIEW.

## Objective

Introduce the foundational organization-owned Course data model for future training content. This ticket adds no application mutation or query layer.

## Product decisions

- Every Course belongs to exactly one Organization; Organization is its owner.
- `title` is required and is deliberately not unique, including within one Organization.
- `description` is optional.
- `CourseStatus` contains `DRAFT` and `PUBLISHED`; new Courses default to `DRAFT`.
- `PUBLISHED` is a schema value only. Publishing transitions and authorization are LMS-023.
- Organization hard deletion cascades to its Courses.

## Database

- Added the inverse `Organization.courses` relation and the required `Course.organization` foreign key with `ON DELETE CASCADE`.
- Added UUID `id`, required `organizationId` and `title`, nullable `description`, defaulted `status`, and standard `createdAt` / `updatedAt` fields.
- Added `@@unique([id, organizationId])` as a candidate key for future same-tenant child references. A future Module can reference `(courseId, organizationId)` so PostgreSQL enforces that the Course and child share a tenant. This follows LMS-016's composite-key defense-in-depth pattern.
- Added `(organizationId, createdAt, id)` for future deterministic organization-scoped Course lists.
- No title unique index or unrelated schema change is included.

## Tenant isolation

The Organization FK guarantees that each Course has an existing owner; it does not authorize access or automatically scope Prisma queries. LMS-019 must use trusted tenant context, scope lists by its `organizationId`, and scope Course details and mutations by both Course ID and trusted `organizationId`. LMS-018 adds no Course store or route.

## Tests

`tests/course-model-postgres.test.ts` exercises the generated Prisma client and PostgreSQL: UUID generation, ownership, `DRAFT` default, explicit `PUBLISHED`, nullable description, timestamps, duplicate titles in one and multiple organizations, invalid Organization FK rejection, composite candidate-key acceptance and cross-tenant rejection, organization-separated results, and hard-delete cascade. CI applies migrations to its dedicated PostgreSQL 16 `lms_platform_test` service and runs `pnpm test:course-model:db`.

## Scope

Included: Prisma schema, Course migration, PostgreSQL integration coverage, database and tenant-isolation documentation, and this ticket record.

Not included: Course CRUD/API/store/UI or mutation validation (LMS-019); Modules (LMS-020); Lessons (LMS-021); Lesson builder (LMS-022); publishing workflow (LMS-023); preview (LMS-024); quizzes, assignments, enrollments, progress, certificates, reporting, notifications, AI generation, or other UI.
