# LMS-024 — Course Preview

## Objective

Provide a read-only admin preview of a Course's Course → Module → Lesson hierarchy for both DRAFT and PUBLISHED states. This ticket does not grant learner access.

## Product decisions

- OWNER and ADMIN with `MANAGE_COURSES` may preview; MEMBER and anonymous users may not.
- DRAFT displays **Draft preview** and explains the Course is unpublished. PUBLISHED displays **Published** and its `publishedAt` value when present.
- Preview never changes lifecycle, content, structure, or ordering. It adds no learner, enrollment, progress, completion, Quiz-attempt, certificate, or public-share behavior.
- Incomplete DRAFT Courses and Modules remain previewable. Empty content and QUIZ receive explanatory placeholders.
- LMS-025 owns Quiz configuration. Later learning-flow tickets own assignment, enrollment, learner access, progress, and completion.

## Preview API

`GET /api/organizations/courses/:courseId/preview` returns `{ course }` with the explicit public Course, Module, Lesson, and type-specific content fields. TEXT is `{ text }`, VIDEO/PDF/IMAGE/LINK is `{ url }`, and QUIZ is `null`. Raw content columns, tenant IDs, parent IDs, and unrelated database fields are excluded. All response statuses set `Cache-Control: no-store`.

Malformed, missing, and foreign Course IDs map to `404 course_not_found`. Tenant and permission errors preserve existing safe codes; unexpected storage errors return `503 course_preview_unavailable` without exposing database details.

## Preview page

`/courses/:courseId/preview` is a protected server-rendered page. It performs trusted tenant and `MANAGE_COURSES` checks before loading Course data and uses the same read-service/store as the API. Missing, foreign, and malformed IDs use Next.js `notFound()`. Anonymous/forbidden requests receive a generic access state without Course data.

The route exports `dynamic = "force-dynamic"` and `revalidate = 0`, matching this repository's Next.js 16.3.6 configuration with Cache Components disabled. Dynamic page responses are private and not statically generated.

## Authorization

Both server entry points call `requireTenantContext()` and `requireOrganizationPermission(tenant.organizationId, "MANAGE_COURSES")`. OWNER and ADMIN are allowed; MEMBER is denied. The page never relies on client-side hiding. No tenant ID is accepted from the URL, query, or header.

## Tenant isolation

The Prisma store scopes Course by `id + organizationId`, Modules by `courseId + organizationId`, and Lessons by `moduleId IN tenant-owned Modules + organizationId`. Query/header tenant forgery does not affect the trusted context. Missing and foreign Course IDs have identical public behavior.

## Read model

One fixed set of three reads loads Course, ordered Modules, and ordered Lessons. Module and Lesson order is `position ASC, id ASC`; gaps are preserved without writes. All reads run in one interactive PostgreSQL `REPEATABLE READ` transaction to observe one consistent MVCC snapshot, with no row lock and no per-Lesson query.

## Rendering security

TEXT is rendered only as escaped React text, preserving newlines with CSS. No raw HTML, Markdown HTML, parser, or `dangerouslySetInnerHTML` is used. The rendering regression test includes `<script>alert("xss")</script>` and `<img src=x onerror=alert(1)>` and checks the static markup.

External VIDEO/PDF/IMAGE/LINK resources are never embedded, fetched, or loaded automatically. The page shows the type and hostname in a resource card. Only HTTPS URLs accepted by `parseLessonUrl()` receive an explicit anchor with `target="_blank"`, `rel="noopener noreferrer"`, and `referrerPolicy="no-referrer"`. Invalid historical URLs have no `href` and display **Resource unavailable**.

## Accessibility

The page uses one Course `<h1>`, hierarchical headings, ordered Module/Lesson lists, visible textual status and type labels, clear link text, keyboard-native anchors, sufficient contrast, responsive layout, and a semantic `<time datetime>` timestamp.

## Tests

`tests/course-preview.test.ts` covers OWNER/ADMIN, MEMBER, anonymous, malformed/missing IDs, safe errors, no-store responses, tenant forgery, public-field mapping, TEXT/URL/QUIZ content shapes, and rendered XSS/empty/status/resource behavior. It verifies no auto-loaded media/embed markup and guards the component against `dangerouslySetInnerHTML`.

## PostgreSQL verification

`tests/course-preview-postgres.test.ts` uses production handlers and the Prisma store with OWNER, ADMIN, MEMBER, anonymous, and two-tenant fixtures. It covers DRAFT and PUBLISHED data, `publishedAt`, empty Courses/Modules, multiple Modules, deterministic ordering, all content types, field exclusion, forged tenant inputs, foreign/missing/malformed IDs, and role access. A coordinated mutation after the preview transaction establishes its snapshot verifies the reader sees a wholly pre-mutation hierarchy; a later read sees the committed mutation.

The suite requires PostgreSQL 16 and the dedicated `lms_platform_test` database in CI. Locally, it reports skipped when `TEST_DATABASE_URL` is not configured.
