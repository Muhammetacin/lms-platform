# LMS-005 — Organization Model

Status: CODE COMPLETE

## Goal

Establish and verify `Organization` as the foundation for multi-tenant organizations while preserving the approved LMS-002 schema. This ticket does not implement organization management or tenant isolation.

## Scope

- Verify the required UUID primary key, `name`, unique `slug`, `createdAt`, and `updatedAt` fields.
- Preserve the existing `OrganizationMembership` relation and `createdAt` index.
- Document current slug uniqueness semantics and defer normalization or case behavior decisions to a future ticket.
- Keep the existing migration history unchanged if it already satisfies these requirements.

## Out of scope

- Slug generation, normalization, lowercasing, uniqueness suffixes, or slug update APIs.
- Organization CRUD, settings, membership workflows, invitations, employee management, authorization, or UI.
- Tenant context (LMS-009), tenant isolation (LMS-010), RLS, middleware, or organization-scoped API enforcement.
- Speculative organization fields or changes to `OrganizationRole`.

## Findings

- The existing `Organization` model has a required UUID primary key generated with Prisma `uuid()`, required `name` and `slug`, required timestamps, and the existing `memberships` relation.
- The LMS-002 migration creates the corresponding UUID, required columns, unique `Organization_slug_key` index, `Organization_createdAt_idx` index, and membership foreign key. No schema correction or new migration is needed.
- `slug` is PostgreSQL `TEXT` with a unique index and no explicit collation, `citext`, expression index, or normalization. Uniqueness follows the configured PostgreSQL collation. The schema does not specify case-sensitive versus case-insensitive semantics or promise slug generation or canonicalization.
