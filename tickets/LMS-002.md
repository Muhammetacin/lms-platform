# LMS-002 — Database Foundation

- Status: CODE COMPLETE
- Type: Foundation
- Priority: P0
- Agent: Development Agent
- Reviewer: QA Agent
- Security: Security Agent

Goal:
Establish the PostgreSQL database foundation for the multi-tenant LMS without implementing LMS product features.

Required stack:
- PostgreSQL
- Prisma ORM
- TypeScript
- Existing Next.js App Router application
- pnpm
- Environment-based database configuration

Scope:
- Add Prisma and configure PostgreSQL.
- Add a Prisma schema foundation.
- Establish database client/server access conventions.
- Add safe database environment-variable examples.
- Add a migration workflow suitable for local development.
- Add minimal database connectivity/health verification without exposing credentials.
- Document database setup and conventions.
- Add relevant tests where practical.

Initial schema scope ONLY:
- User
- Organization
- OrganizationMembership

Required relationships:
- One user can belong to multiple organizations.
- One organization can have multiple users.
- OrganizationMembership contains a defined role.
- Stable IDs.
- createdAt / updatedAt timestamps.
- Appropriate unique constraints and indexes.

Do NOT implement:
- Teams
- Courses
- Lessons
- Quizzes
- Assignments
- Progress
- Certificates
- Reports
- Notifications
- Billing
- AI
- Authentication
- Authorization
- Tenant isolation enforcement

Multi-tenant requirements:
- OrganizationMembership is the source of organization membership.
- Client-provided tenant IDs must never become trusted authorization context.
- Document how tenant isolation will later be enforced.
- Do not claim that full tenant isolation is implemented; that belongs to LMS-010.

Security:
- Never commit database credentials.
- Use ignored environment files.
- Validate required database configuration.
- Never log passwords or credential-bearing connection strings.
- Document least-privilege principles.
- Do not expose the database connection through a public API route.

Acceptance criteria:
- Prisma installed and configured.
- PostgreSQL datasource configured through environment variables.
- Schema contains only User, Organization and OrganizationMembership for product entities.
- Relationships and constraints defined.
- Migrations can be created/applied locally.
- Database client convention documented.
- Database setup documented.
- .env.example contains safe placeholders only.
- No secrets committed.
- Existing lint/typecheck/build continue to pass.
- Relevant database tests pass.
- No LMS-003+ functionality implemented.
- Material architecture decisions documented as ADRs.

Definition of Done:
- Requirements implemented exactly within scope.
- Acceptance criteria pass.
- Lint/typecheck/build pass.
- Database/migration verification passes.
- Security review passes.
- Documentation updated.
- QA approval recorded.
- Architecture changes documented.
- No secrets committed.
- CEO/PO approval required before production use.
