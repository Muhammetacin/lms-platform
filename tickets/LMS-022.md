# LMS-022 — Lesson Builder

## Objective

Provide secure backend authoring operations for Lessons under `Organization → Course → CourseModule → Lesson`: list, create, detail, metadata/content update, reorder, and delete. Mutations apply only while the parent Course is DRAFT, and positions remain contiguous within one Module.

## Product decisions

- Preserve the LMS-021 hierarchy. Lesson has no `courseId`.
- Add exactly nullable `textContent String?` and `contentUrl String?`; no generic JSON content or Quiz model.
- `TEXT` uses source text. `VIDEO`, `PDF`, `IMAGE`, and `LINK` use HTTPS resource URLs. Draft content may be empty.
- `QUIZ` remains creatable but has no LMS-022 content; content update returns `409 quiz_content_not_available`.
- File upload, storage infrastructure, remote URL fetching, preview/rendering, Course publishing, and learner flows remain out of scope.
- LMS-023 owns publication completeness and status transitions; it must use the same parent Course lock. LMS-024 owns safe rendering and preview.

## API

- `GET /api/organizations/courses/:courseId/modules/:moduleId/lessons` — ordered summaries.
- `POST` on that route — exact body `{ title, type }`; create at the end and return `201`.
- `GET /api/organizations/courses/:courseId/modules/:moduleId/lessons/:lessonId` — detail with a type-specific `content` object.
- `PATCH` on the detail route — exact allowlist `{ title?, type? }`, at least one field.
- `DELETE` on the detail route — delete and compact.
- `POST .../:lessonId/move` — exact body `{ position }`.
- `PUT .../:lessonId/content` — exact body `{ text }` for TEXT or `{ url }` for VIDEO/PDF/IMAGE/LINK.

Every mutation uses `isTrustedAuthRequest` and the repository's JSON conventions. Every response, including authorization and error responses, sends `Cache-Control: no-store`.

## Lesson content model

The migration adds nullable PostgreSQL `TEXT` columns `textContent` and `contentUrl`, represented by `String?` in Prisma. `Lesson_type_content_consistency_check` prevents URL content on TEXT, text content on VIDEO/PDF/IMAGE/LINK, and either value on QUIZ. It permits null content in DRAFT Lessons.

Create never accepts content. Detail exposes only `{ content: { text } }`, `{ content: { url } }`, or `content: null` for QUIZ; list excludes content. Internal content columns are never returned directly. A real type change clears both columns in the same transaction; a same-type update preserves them.

## Validation

- Lesson title is trimmed, 2–160 Unicode code points, and rejects control characters and unpaired surrogates.
- Create requires one of the six exact LessonType strings and rejects all fields except `title` and `type`.
- PATCH accepts only `title` and/or `type`; `moduleId` and `position` are immutable there.
- Move position must be a safe integer in `1..Lesson count`.
- TEXT preserves formatting whitespace, normalizes CRLF/CR to LF, maps blank content to null, permits tab/newline, rejects NUL and other disallowed controls/unpaired surrogates, and allows at most 100,000 Unicode code points.
- URL content trims, maps blank to null, allows at most 2,048 characters, and requires an absolute HTTPS URL with a hostname and no credentials. No request is made to the URL.
- Content bodies use a strict type-specific allowlist. QUIZ returns its stable 409 error before content parsing.

## Authorization

All endpoints require trusted tenant context and existing `MANAGE_COURSES`. OWNER and ADMIN can manage Lessons; MEMBER and anonymous callers use existing authorization errors. No new role or capability is introduced.

## Tenant isolation

The only trusted tenant key is `requireTenantContext().organizationId`. Reads validate Course, then Module scoped by `{ id, courseId, organizationId }`, then Lesson scoped by `{ id, moduleId, organizationId }`. The Lesson model does not duplicate `courseId`. Foreign, malformed, and missing resources map to the same safe 404 at their hierarchy level. Client-supplied tenant headers and query values cannot select an Organization.

## Ordering

Lesson positions are positive, unique per Module, and contiguous `1..N` after Builder structural writes. Create allocates `MAX(position) + 1` while holding the parent lock. Move parks the selected Lesson at an unused positive sentinel, shifts the intervening rows in a collision-safe direction, and assigns the destination. Delete and compaction are atomic. IDs remain stable. Position-only SQL writes preserve `updatedAt`.

## Concurrency

Each Lesson mutation begins a transaction and locks the parent Course with the LMS-020 predicate and `SELECT ... FOR UPDATE`; that lock remains through Course status validation, Module/Lesson validation, and the mutation. This serializes Lesson create/move/delete/content/metadata writes with LMS-020 CourseModule changes and the LMS-023 publish operation. Concurrent create/create, move/move, move/create, delete/move, and Module-delete/Lesson-mutation integration cases assert committed state and ordering. Failed reorders roll back fully.

## Published Course behavior

List and detail are allowed on PUBLISHED Courses. Create, metadata update, content update, move, and delete return `409 published_course_structure_locked` after the locked status check. The PostgreSQL suite holds the Course lock during a competing status transition and verifies that the waiting Lesson mutation sees PUBLISHED and does not write.

## Database constraints

The LMS-022 migration adds only the two nullable Lesson content columns and the stable type/content CHECK constraint. It does not change enum values, hierarchy, Module/Course fields, or authorization models. Direct SQL tests attempt invalid TEXT+URL, VIDEO+text, QUIZ+text, and QUIZ+URL combinations and require PostgreSQL rejection. Existing nullable draft states remain valid.
