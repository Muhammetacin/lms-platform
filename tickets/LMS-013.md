# LMS-013 — Employee Profile

Status: IN PROGRESS

## Objective

Add a small organization-scoped employee profile on the existing `OrganizationMembership` boundary established by LMS-012.

## Blocker

## Approved product decision

- Reuse `employeeName` and add optional `jobTitle`, `department`, `phone`, and `employeeNumber` fields to `OrganizationMembership`.
- `employeeNumber` is unique within one organization only. It is not globally unique. Email remains global identity data on `User`.
- OWNER and ADMIN can view and edit profiles in their organization. MEMBER can view and edit their own profile only.
- MEMBER self-service can change `employeeName`, `jobTitle`, `department`, and `phone`. It cannot change email, role, active state, organization, tenant, or employee number. OWNER/ADMIN may manage employee number.
- Add `GET` and `PATCH /api/organizations/employees/:employeeId/profile`. Preserve LMS-012 lifecycle behavior; do not add role changes, activation, reactivation, or deactivation here.
- Do not add avatars or unrelated HR data.

## Implementation conventions

- Keep all profile fields on the membership; every store operation scopes by both membership ID and trusted organization ID.
- Use the existing role hierarchy and add `VIEW_EMPLOYEE_PROFILES` (minimum ADMIN) and `MANAGE_OWN_PROFILE` (minimum MEMBER). The handler must verify that a MEMBER target belongs to the authenticated user.
- Trim optional text, preserve case, allow `null` to clear optional fields, reject blank strings/control characters, and cap them at 120 Unicode code points. `employeeName` uses LMS-012's 2–120 code point rule. Phone is not format-parsed.
- Enforce organization-local employee-number uniqueness in PostgreSQL and map collisions to a generic 409.
- LMS-058 is not present in the repository. Do not create another audit system; document profile audit logging as a dependency on LMS-058.

- Added unit and PostgreSQL integration coverage and updated authorization, employee, database, and tenant-isolation documentation.
