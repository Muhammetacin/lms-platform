# LMS-013 — Employee Profile

Status: BLOCKED

## Objective

Not defined yet. The repository does not contain an LMS-013 ticket or acceptance criteria for an employee profile.

## Blocker

The current `main` branch defines `OrganizationMembership.employeeName` as an organization-specific employee display name. LMS-012 exposes only `{ id, email, name, role, active }` and explicitly leaves HR data and employee UI out of scope. No repository requirement defines additional profile fields, profile behavior, or whether this ticket is a read-only view, administrator-managed data, or employee self-service.

This is a product and architecture decision. `User.name` and `User.email` are global identity data shared across an employee's organizations. Writing organization-specific profile values there could change what another organization sees. Additional fields on the membership or a separate organization-owned profile would have different privacy, validation, migration, and tenant-isolation requirements. The existing authorization matrix also does not define profile self-service: employee detail reads use `VIEW_ORGANIZATION` (OWNER, ADMIN, and MEMBER), while employee updates use `MANAGE_MEMBERS` (OWNER and ADMIN). `VIEW_OWN_MEMBERSHIP` exists, but is not wired to an employee-profile endpoint.

Implementing without these decisions would invent product requirements and could expose or mutate personal data under the wrong tenant boundary.

## Options for Product

1. **Use the existing employee record as the profile.** Limit the profile data to LMS-012's current response fields and `employeeName`; do not add profile columns. Specify the required profile screen/API behavior and who may view it.
2. **Define an organization-owned profile.** Approve an exact field list, required/optional rules, validation and visibility, and who may read or edit each profile. Keep organization-specific values on the membership or another explicitly tenant-owned model; keep global identity data on `User`.

## Recommendation

Start with option 1 if LMS-013 is intended only to present the employee information already managed by LMS-012. If additional profile information is required, choose option 2 and approve the exact fields and access rules before implementation. Do not put organization-specific profile values on the global `User` record.

## Product decision required

Product/COO/CEO must confirm:

- the exact profile fields and which are required, optional, or read-only;
- whether the profile is a view of existing employee data or adds organization-owned data;
- whether employees may view or edit their own profile, and which roles may view or edit other employees' profiles;
- the required UI/API surface and acceptance criteria.

Once approved, record the decision and acceptance criteria here before moving the ticket to READY.

## Implementation

None. Implementation is blocked pending the product decisions above. No application code, schema, migrations, or tests were changed.
