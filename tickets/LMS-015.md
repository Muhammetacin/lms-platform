# LMS-015 — Team Model

Status: CODE COMPLETE

## Objective

Introduce Teams as organization-owned groups with a required name and optional description. Team names are unique within an organization. Provide a tenant-scoped CRUD API for the model, reusing the LMS-008 `VIEW_ORGANIZATION` and `MANAGE_TEAMS` capabilities.

## Scope boundaries

- Team membership, member counts, managers, courses, assignments, reporting, and notifications remain out of scope; membership is LMS-016.
- Do not add parallel audit logging; Team mutation auditing depends on LMS-058.
- Keep the existing `OWNER`, `ADMIN`, and `MEMBER` roles.

## Implementation

- Added the Prisma `Team` model and the `20261006100000_teams` migration. The organization/name unique index is case-sensitive under the existing PostgreSQL collation; organization deletion cascades to its Teams.
- Added GET/POST list/create and GET/PATCH/DELETE detail routes under `/api/organizations/teams`, strict name/description validation, explicit response selection, scoped Prisma queries, and safe duplicate-name 409 handling.
- Reused `VIEW_ORGANIZATION` for reads and `MANAGE_TEAMS` for management. Create ownership always comes from `requireTenantContext()`; request tenant/owner/role fields are rejected.
- Added unit tests and a real PostgreSQL integration suite using the production Prisma Team store and handlers. Added CI wiring and updated database, authorization, tenant-isolation, and Team documentation.
- Team membership remains LMS-016; no audit system was added, per the LMS-058 boundary.
