- Added a separate PostgreSQL 16 Chromium `e2e` CI job with frozen install, migrations, browser installation, failure artifacts, and no changes to the existing PostgreSQL regression job.

## QA hardening follow-up

- `playwright.config.ts` sets `reuseExistingServer: false`, so Playwright always launches its configured Next.js process. The server remains bound to `127.0.0.1:3100` and receives `DATABASE_URL` from `E2E_DATABASE_URL`; the existing loopback and dedicated-database guards remain active. Next.js is given an explicit `--port 3100`, so an occupied port is a startup error rather than an automatic move to another port. A live occupied-port probe failed with `http://127.0.0.1:3100 is already used` before any browser test ran.
- E2E-002 now logs in, reads the Courses metric from the dashboard, creates a uniquely named Course in the browser, then requires the dashboard total to equal the previously read value plus one. It no longer assumes an empty database. A retry probe deliberately failed after the first Course was saved; Playwright retried with that row still present and the second attempt passed its count-delta assertion.
- No product, API, database schema, migration, auth, tenant, or fixture-reset changes were made for this follow-up.
