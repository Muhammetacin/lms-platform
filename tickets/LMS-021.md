# LMS-021 — Lesson Model

Status: IN PROGRESS — verification pending

## Objective

Introduce the database/domain foundation for tenant-owned Lessons within Course Modules. This ticket adds the `LessonType` enum, Prisma model, PostgreSQL migration, integrity tests, CI step, and documentation. Lesson API, content, Builder, and Quiz implementation are out of scope.

## Product decisions

- `LessonType` is `TEXT`, `VIDEO`, `PDF`, `IMAGE`, `LINK`, or `QUIZ`.
- `Lesson.type` is required and has no default so a future Builder must choose explicitly.
- `QUIZ` is reserved for later Quiz work beginning in LMS-025; LMS-021 adds no Quiz model or relation.
- Lesson has only title, type, position, ownership, and timestamps; no description, status, or content payload.
- Duplicate titles are allowed. Lesson title validation is deferred to LMS-022.
- Contiguous position management belongs to LMS-022; LMS-021 enforces only positive, unique-per-Module positions.
- LMS-022 must use the LMS-020 Course `SELECT ... FOR UPDATE` lock and reject structure/content writes for PUBLISHED Courses.

## Lesson model

`Lesson` stores UUID `id`, required UUID `organizationId` and `moduleId`, required text `title`, required `LessonType type`, one-based integer `position`, and required `createdAt`/`updatedAt` timestamps. It has candidate key `(id, organizationId)`, unique `(moduleId, position)`, and index `(organizationId, moduleId, position)`.

## LessonType

The PostgreSQL enum contains `TEXT`, `VIDEO`, `PDF`, `IMAGE`, `LINK`, and `QUIZ`. The model has no type default and no type-specific content fields.

## Hierarchy

Lesson belongs to exactly one CourseModule; its Course is derived through `CourseModule → Course`. There is no `courseId` on Lesson. Organization exposes the inverse `lessons` relation; CourseModule exposes `lessons`.

## Tenant integrity

Lesson has a direct cascading Organization FK and a composite cascading `(moduleId, organizationId) → CourseModule(id, organizationId)` FK. PostgreSQL rejects a direct Lesson insert that combines Organization B with Organization A's Module. The `(id, organizationId)` candidate key is verified as a target for future tenant-owned child FKs.

## Ordering

Positions are one-based. PostgreSQL checks `position >= 1` and enforces unique `(moduleId, position)`. Position 1 is valid in separate Modules, and duplicate titles are valid in one Module. The database does not enforce gaplessness; LMS-022 owns contiguous create/move/delete behavior.

## Cascade behavior

Deleting a Module deletes its Lessons. Deleting a Course cascades through Modules to Lessons. Deleting an Organization deletes its Lessons through the direct Organization FK while existing Course and Module cascades remain intact.

## PostgreSQL tests

`tests/lesson-model-postgres.test.ts` runs directly against PostgreSQL 16 and requires `TEST_DATABASE_URL` to target `lms_platform_test`. It covers UUID generation, ownership/relations, all enum inserts, required type and position with no type default, positions 1/0/negative, duplicate position rejection, same position across Modules, duplicate titles, missing Module, candidate key behavior, organization separation, and Module/Course/Organization cascades.

## Security verification

The test directly inserts a Lesson with `organizationId = Organization B` and `moduleId = CourseModule A`; PostgreSQL must reject it with a composite foreign-key violation, and no row may remain. The application layer is not used to simulate this security requirement.

## Scope boundaries

No Lesson API, Builder, editor, CRUD/move handler, UI, content JSON or fields, upload/storage, video/PDF/image handling, rich text, Quiz model, Question, QuestionOption, Attempt, or Lesson status is included. `QUIZ` is only a reserved enum value.
